# ADR-0012：V3 记忆网络与检索接口

## 状态

已接受，2026-08-09。

## 背景

Jarvis 已有已确认长期记忆、领域业务表、Obsidian 知识桥接和 pgvector 语义索引。V3 需要表达目标、技能、主题、项目之间的关系与事件时间线，但不能引入新的图数据库，也不能让派生关系绕过原始来源权限。

V3-1 已实现 `memory_entities`、`memory_relations` 和 `memory_events`。实现复核发现，正式长期启用前仍需明确并发唯一性、关系历史、事件关联完整性和全局召回预算。

## 决策

1. PostgreSQL 继续是唯一事实源，不引入 Neo4j、FalkorDB、Redis 或独立向量库；
2. 领域业务表仍是目标、任务、错题、投资记录等领域事实的权威来源；
3. 记忆网络保存经用户确认的跨领域实体、关系和事件引用，不能反向静默修改领域事实；
4. 候选默认不参与聊天上下文，只有 confirm 后才可检索；
5. 记忆网络模块对调用者只提供三个接口：

```text
extract_candidates(scope) -> CandidateBatch
decide(candidate_id, action) -> DecisionResult
retrieve(query, budget, for_cloud) -> MemoryContext
```

6. 规则抽取、本地 Qwen、PostgreSQL 和语义索引是内部实现，不暴露为调用者必须编排的步骤；
7. 实体必须具有用户范围内的数据库级规范化唯一性；
8. 关系必须支持有效期结束后再次成立，不得用一个永久唯一三元组抹平历史 episode；
9. 事件与实体关联必须有可验证的引用完整性和可索引查询路径；V3-1.1 优先迁移到关联表；
10. 检索最多遍历 2 hop，实体、关系、事件合计最多返回 12 项；
11. 8K token 预算以最终渲染上下文为准，包含格式和溯源开销；
12. 每次读取和发送云模型前重新检查来源状态、用户所有权与 `cloud_allowed`；
13. 归档、合并、来源停用必须同步使关系、事件可见性和派生语义索引失效；
14. 语义索引不可用时退回关键词与关系遍历，不影响事实源写入。

## 结果

- 调用方不需要理解抽取器、图遍历和向量同步细节；
- 并发抽取和历史关系可以通过数据库约束验证；
- 记忆网络不会成为绕过领域权限的第二事实源；
- 查询预算在一个接口处统一执行，不会由各调用方各自裁剪；
- V3-1.1 需要新增迁移、并发测试、历史关系测试和全局预算测试。

## 未采用方案

- 直接引入图数据库；
- 让 Qwen 自动写入 active 记忆；
- 继续把每类召回数量分别解释为“总召回上限”；
- 让调用方自行组合实体、关系、事件和语义结果。
