# ADR-0007：本地语义索引与权限一致性

## 状态

已接受，2026-08-02。

## 背景

Jarvis 已有经过用户确认的长期记忆和受逐篇权限控制的 Obsidian 文档。纯关键词检索对“表达不同但含义相近”的问题召回不足，但新增独立向量数据库会增加常驻资源、运维复杂度和权限同步风险。

## 决策

1. 使用现有 PostgreSQL 17 的 pgvector 扩展；
2. 使用本机 Ollama `bge-m3:latest` 生成 1024 维向量；
3. Embedding 地址仅允许本机回环地址；
4. PostgreSQL 正文保持事实源，向量表不复制正文；
5. 用内容哈希和索引版本识别陈旧条目；
6. 初期执行精确余弦距离检索；
7. 关键词与语义结果采用 RRF 融合；
8. 每次读取向量结果后重新检查当前来源状态、哈希和云端权限；
9. 删除、停用和检索权限关闭时同步使派生条目失效；
10. 索引或模型故障时自动回退关键词，不影响事实源写入。

## 理由

- 当前为单用户、个人规模数据，精确检索足够且召回可预测；
- 复用 PostgreSQL 可减少一个独立数据库进程；
- 本地 Embedding 避免将私人记忆和笔记发送给云服务；
- 查询时重新关联事实源，可以防止陈旧向量绕过最新权限；
- 可重建索引让迁移、模型升级和故障恢复更简单。

## 后果

- PostgreSQL 容器必须使用带 pgvector 的同主版本镜像；
- 索引重建会占用一定 CPU / 内存和本地 Ollama 时间；
- Embedding 模型、维度或分片策略变化时必须提高索引版本并重建；
- 数据规模增加后需要基于真实延迟和召回测试再决定是否使用 HNSW；
- Mem0 后续只能通过适配器读取正式记忆和派生索引，不能成为事实源。
