# ADR-0009：模型只能提出工具请求，副作用必须由 Tool Gateway 仲裁

## 状态

已接受，2026-08-02。

## 背景

Jarvis 已有 Agent、可恢复工作流、长期记忆和逐任务 DeepSeek 授权。下一步若让模型直接调用文件、日历、邮件或浏览器，会绕过用户已确认的安全边界，并产生重复执行、参数漂移、凭据泄露和无法追责的风险。

## 决策

1. LLM 输出永远不是最终工具参数；
2. 所有工具调用必须经过统一 Tool Gateway；
3. 每个工具必须有版本化定义、输入 Schema、作用域、风险、Agent 白名单、幂等和审计声明；
4. Agent Catalog 与 Tool Registry 必须双向允许，任一不允许即拒绝；
5. R0/R1 可以自动执行，但必须记录结果；
6. R2 必须先生成完整预览，允许用户修改、批准或拒绝；
7. R2 批准后仍需单独执行，执行前重新校验全部参数和权限；
8. R3 不得注册为 Agent Tool，没有确认或执行入口；
9. 投资交易、支付、删除数据和凭据操作固定属于 R3；
10. 相同幂等键与相同参数只能产生一次副作用；不同参数重用同一键必须拒绝；
11. 可能产生副作用的工具不自动重试；执行状态不明时停下等待人工检查；
12. 工具参数进入 Gateway 前执行敏感信息拦截，凭据永不进入 Agent 参数和审计正文；
13. 当前文件写入只允许项目 `.data/tool-sandbox` 下的受控文本格式；
14. 未连接的 Provider 可以登记风险契约，但不能接受执行请求；
15. 工具审批和付费模型授权在 Approval Center 统一可见，但二者权限互不替代。

## 理由

- 把模型推理和真实副作用分离；
- 让用户始终掌握会改变系统状态的最后决定；
- 用 Schema、白名单和路径校验防止模型扩大权限；
- 用幂等键与单次批准避免重放和重复副作用；
- 先建立稳定安全边界，再接入 n8n、日历、邮件和浏览器。

## 后果

- R2 比普通聊天多一次预览和一次执行确认；
- 工具开发必须同时维护定义、策略、测试和审计；
- 不确定是否执行成功时不会自动重试，可能需要人工检查；
- 当前只能写受控沙箱文件，不能修改用户任意文件；
- 日历、邮件、浏览器和外部账号暂时不可用；
- Approval Center 成为未来所有外部副作用的统一控制面。

## 被拒绝的方案

### 让 Agent 直接调用 Python 函数或 SDK

拒绝。无法保证统一的风险判断、用户确认、幂等和审计。

### 用户批准后立即执行

拒绝。批准范围与真正产生副作用之间仍应保留最后一步，让用户能够重新检查。

### 把 R3 改成“每次确认即可执行”

拒绝。用户已明确投资交易、支付、数据删除和凭据操作永不自动执行；确认不能降低其风险等级。

### Sprint 29 直接连接真实外部账号

拒绝。先用本地受控工具证明 Gateway 状态机、审批和重放安全，再引入 Provider 与凭据隔离。
