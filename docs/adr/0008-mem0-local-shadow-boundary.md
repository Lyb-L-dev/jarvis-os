# ADR-0008：Mem0 只能作为可熔断的本地影子记忆引擎

## 状态

已接受，2026-08-02。

## 背景

Jarvis 已有用户确认的正式记忆、来源追踪、云端授权和本地语义索引。直接让 Mem0 接管记忆会产生双事实源、隐式更新、默认云服务、删除同步和故障耦合风险。当前阶段需要先用真实个人场景证明候选质量，而不是替换已经可控的系统。

## 决策

1. `memories` 是唯一正式记忆事实源；
2. Mem0 通过 `MemoryEngine` Adapter 接入，不被聊天和上下文直接依赖；
3. Mem0 只运行固定评测场景并保存派生影子向量；
4. 不实现影子候选转正式记忆的接口；
5. LLM 和 Embedding 显式配置为本机 Ollama；
6. Vector Store 显式配置为现有本机 PostgreSQL pgvector；
7. 遥测固定关闭，工作目录固定在项目 `.data`；
8. Ollama 地址仅允许回环地址；
9. 模型缺失时拒绝运行，不允许 SDK 自动下载；
10. 初始化后核验实际 provider，防止 SDK 默认回落到 OpenAI 或 Qdrant；
11. Mem0 失败不得影响规则、Qwen、聊天、记忆中心或正式上下文；
12. 必须完成个人评测集、达到 80% F1 且安全违规为 0，才允许讨论后续转正；
13. 即使达到门槛，正式写入仍需新的架构决策与用户批准。

## 理由

- 避免双事实源和隐式记忆修改；
- 先测量，再决定是否扩大权限；
- 复用本机 Ollama 和 PostgreSQL，减少常驻组件；
- 允许随时关闭 Mem0，不破坏既有功能；
- 把 Mem0 通用包的云端默认行为限制在不可达的配置之外；
- 保留候选来源和人工质量判断，便于持续评估。

## 后果

- 当前 Mem0 只能证明候选质量，不能提升正式对话上下文；
- 单个 Mem0 场景在当前 4B 模型上约需 50–60 秒，不适合每条聊天后自动运行；
- Mem0 专用 Qwen 别名使用 16K 上下文，会增加一次运行的显存与内存占用；
- Mem0 通用依赖体积高于自研规则适配器；
- 影子向量和历史库属于可审计的派生数据，但当前不提供自动清理；
- 未来若允许影子候选转正，必须补充冲突处理、显式确认、派生记录关联和删除一致性设计。

## 被拒绝的方案

### 让 Mem0 直接拥有正式记忆

拒绝。会破坏现有确认、权限、审计和删除边界。

### 使用 Mem0 默认配置

拒绝。默认 LLM、Embedding 和 Vector Store 可能指向云端 OpenAI 与 Qdrant，不符合本地优先和凭据边界。

### 每条聊天自动运行 Mem0

拒绝。当前单次延迟和资源占用不适合 16 GB 内存与 4 GB 显存设备，也没有必要在准确率评测前增加后台负载。

### 只用关键词评分

拒绝。Mem0 可能保持语义但改变语言，关键词会误判；采用本地 BGE-M3 多语言语义评分。
