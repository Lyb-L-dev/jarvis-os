# ADR-0003：DeepSeek 逐任务确认与最小化运行记录

- 状态：接受
- 日期：2026-08-02
- 适用版本：Jarvis OS v2.0

## 背景

Research 和 Growth 需要复杂推理能力，但 DeepSeek 按量计费，云端调用也涉及数据范围。运行审计又不能复制用户的完整提问、笔记或文件正文。

## 决策

Research 与 Growth 将 DeepSeek 声明为深度推理首选能力，但采用 `explain_and_confirm_per_run` 策略：

1. Jarvis 说明为什么需要 DeepSeek；
2. 列出它负责的步骤；
3. 列出发送的数据类别；
4. 提供 MiMo 和本地 Qwen 等替代方案；
5. 用户确认后，只在这一次 Agent Run 已披露的步骤内调用。

后台任务不得静默调用 DeepSeek。新增步骤、扩大数据范围、任务恢复后跨越授权边界或开始新 Run 时必须重新确认。

Agent Run 与 Step 只保存结构化 ID、状态、时间、错误代码和数据引用，不保存：

- 用户提问正文；
- 模型 Prompt；
- 笔记或文件正文；
- 邮件正文；
- API Key、Token、密码或 Cookie；
- 完整工具响应。

需要展示的动作预览保存在具备正常访问控制的业务草稿区，运行记录只持有 `preview_ref`。

## 结果

- 用户可以理解付费模型在任务中的真实作用；
- 一次确认不需要在同一已披露流程中反复打断；
- 审计记录可追踪但不会变成第二份私人数据副本；
- DeepSeek 未获授权或不可用时可以使用用户选择的降级方案。
