# Sprint 8：OpenClaw 微信通道（延期）

## 当前决定

本阶段不在主力 Windows 电脑安装 OpenClaw，也不阻塞 Jarvis 后续开发。

原因：

- OpenClaw 原生插件与 Gateway 在同一进程运行，不具备独立沙箱；
- 微信通道由腾讯微信团队以外部插件形式维护，不属于 OpenClaw 核心；
- 用户当前只在虚拟机中使用过 OpenClaw，主机环境尚未建立隔离和回滚能力；
- Jarvis 已包含长期记忆、投资、模型密钥和个人数据，不能用“应该安全”代替验证。

## 未来重新启用的安全门槛

- [ ] 只在虚拟机或独立低权限 Windows 用户中安装；
- [ ] 虚拟机创建可回滚快照；
- [ ] 不挂载主机个人目录、Jarvis 项目目录或 Docker Socket；
- [ ] 不共享主机浏览器配置、SSH 密钥、API Key 和剪贴板；
- [ ] OpenClaw 只获得访问一个受限 Jarvis Channel API 的权限；
- [ ] 微信只开放个人私聊和单一身份白名单；
- [ ] 插件版本、来源、文件哈希和权限经过人工审计；
- [ ] 禁用 `exec`、文件系统、浏览器和任意网络工具；
- [ ] 重复消息、非白名单、断线、重启和密钥轮换测试全部通过；
- [ ] 虚拟机中的稳定性验收至少持续一周。

## 当前替代方案

- 电脑端继续使用 Jarvis Dashboard；
- Windows Companion 继续负责桌面通知与自动语音播报；
- Sprint 9 先完成自动备份、恢复验证、跨模块闭环和故障降级；
- OpenClaw 后续恢复时只作为可拔插通道，不修改 Jarvis 核心数据所有权。
