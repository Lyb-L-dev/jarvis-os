## 0. 决策摘要

### 0.1 已冻结的产品决策

1. V4 的定位是 **可靠桌面发行层 + 有限 Windows 原生体验**，不是网页套壳，也不是新增一批 AI 业务模块。
2. V3-4b 对话双翼工作台继续作为唯一主界面和默认入口。
3. V4 必须交付可安装、可启动、可诊断、可恢复、可更新、可卸载的 Windows App。
4. V4 必须交付六项原生交互：全局快捷键、快速输入窗口、通知联动、受控文件接入、按住说话、运行状态中心。
5. V4 必须提供可选开机启动；默认关闭，用户可以随时撤销。
6. 快速窗口、通知和文件入口必须进入现有对话、提醒、知识或工具事实源，不建立桌面专用业务数据库。
7. 所有写入、付费、外部副作用和高风险工具继续遵守 V3 的模型授权、隐私路由和 R0–R3 审批规则。
8. V4 只支持 Windows 11 x64 单用户、本地优先场景；不改造手机和平板端。
9. V4 不新增 Agent 领域，不重写记忆、向量数据库、模型路由或 Tool Gateway。
10. 现有源码启动方式在 V4 Stable 前保留为开发和恢复入口。

### 0.2 待证据冻结的技术决策

以下不是产品范围问题，V4-0 必须实测后写入 ADR-0015：

- Tauri 2 是否满足最终 Desktop Shell 要求；
- Next.js 桌面构建能否完全静态嵌入，是否需要短期 Node Sidecar；
- FastAPI、Companion 与可选 Worker 的打包形式和资源预算；
- WebView2 的真实 Origin、麦克风权限、协议激活和文件访问边界；
- 安装包、内存、CPU、冷/热启动和更新差分的正式预算；
- Windows 代码签名、更新渠道和发布基础设施。

若 Spike 证明首选技术不可行，可以替换实现，但不能删除本 PRD 的产品能力或破坏安全边界。

## 1. 产品定义

### 1.1 产品定位

> 让 Jarvis 成为可安装、可唤醒、可感知运行状态、可通过通知和文件与 Windows 协作的本地个人 AI 桌面系统。

V4 的价值不是把浏览器藏起来，而是让用户不再需要理解 PowerShell、Python、npm、端口、Sidecar 或 Docker 启动顺序，同时把 Jarvis 从“需要主动打开的网站”变成“随时可唤醒但不会越权打扰的桌面助手”。

### 1.2 当前问题

当前版本已经具备对话、RAG、长期记忆、工具、审批、主动提醒、本地语音和 V3-4b 双翼工作台，但日常使用仍有明显门槛：

- 启动链条依赖脚本和多个运行时，失败原因对普通用户不透明；
- 浏览器入口缺少单实例、窗口生命周期、系统托盘和完整更新语义；
- 临时想到问题时必须先找到网页，交互成本偏高；
- Windows 通知与 Jarvis 上下文没有形成可靠的返回路径；
- 文件无法以明确、可控、可审计的方式交给 Jarvis；
- 用户难以快速判断 Core、PostgreSQL、Ollama、通知和语音到底是否可用。

### 1.3 目标用户与环境

V4 首版服务一个明确场景：

- 用户：Jarvis OS 的单一所有者；
- 设备：个人 Windows 11 x64 电脑；
- 权限：普通用户权限为默认；
- 数据：本地 PostgreSQL/pgvector 是唯一业务事实源；
- 模型：云端与 Ollama 本地模型按现有策略并存；
- 依赖：Docker Desktop、PostgreSQL 容器、Ollama 和可选 n8n 保持可见外部依赖；
- 网络：允许断网降级，本地能力仍按当前边界工作。

### 1.4 成功标准

用户安装后无需终端即可完成首次启动、日常唤醒、对话、通知返回、文本文件交接、语音输入、故障诊断、升级和退出；任何失败都不会悄悄丢数据、制造重复进程或绕过审批。

## 2. 产品目标与非目标

### 2.1 产品目标

| 编号 | 目标 | 产品结果 |
|---|---|---|
| G1 | 降低使用门槛 | 从开始菜单/快捷方式启动，不需要终端和源码目录 |
| G2 | 建立可靠运行时 | 依赖、迁移、Sidecar、退出和恢复由统一 Supervisor 管理 |
| G3 | 缩短唤醒路径 | 一个全局快捷键即可进入可输入状态 |
| G4 | 建立 Windows 协作 | 通知、文本文件和麦克风进入统一、可确认的 Jarvis 流程 |
| G5 | 保持可信边界 | 桌面入口不绕过 FastAPI、Tool Gateway、模型授权或审批 |
| G6 | 形成可发布产品 | 安装、升级、回退、卸载、诊断和文档具备真实证据 |

### 2.2 明确非目标

V4 不包含：

- Android、iOS、平板专用 UI、跨设备同步；
- macOS、Linux、Microsoft Store；
- 插件市场、第三方扩展商店、大量新 Agent；
- 多用户、账号体系、团队协作和云端托管版；
- 记忆网络、Embedding、向量数据库或模型路由重写；
- 常驻唤醒词、后台持续录音；
- 持续监控屏幕、剪贴板、摄像头、键盘或任意目录；
- 无确认接管电脑、自动批准工具、支付或外部行动；
- PDF、Office、压缩包、图片 OCR 的通用文件理解；
- 自动捆绑安装 Docker Desktop、Ollama 或模型权重。

## 3. 产品原则

### 3.1 一个对话事实源

主窗口和快速窗口只是不同入口。消息、回答、引用、审批和工具结果都写入现有会话模型；不存在“快速窗口历史”和“主窗口历史”两套事实。

### 3.2 主动但不越权

Jarvis 可以提醒、展示和建议，但通知、托盘和快捷窗口不能成为高风险批准入口。任何 R2/R3、付费、隐私升级或外部副作用都必须回到主窗口的标准确认界面。

### 3.3 本地优先且边界可见

运行状态、文件来源、将使用的模型范围和是否会写入知识库必须可见。敏感文件默认只允许本地处理；需要云模型时沿用现有隐私确认语义。

### 3.4 先预览，后行动

文件导入、配置迁移、开机启动、升级和删除数据都必须显示将发生什么。取消操作不得留下半完成状态。

### 3.5 可降级，不伪装

Ollama、语音、通知或可选 Worker 失败时，系统可以进入降级模式，但必须明确缺失能力；PostgreSQL、迁移或 Core 失败时不得显示“已就绪”。

### 3.6 桌面能力保持小接口

Desktop Shell 只暴露窗口、托盘、快捷键、通知激活、受控文件授权和运行时状态等窄接口。业务写入仍通过 FastAPI；Runtime Supervisor 封装复杂启动与恢复逻辑，调用方只消费状态和受控动作。

### 3.7 所有原生能力可撤销

全局快捷键、开机启动、通知动作和文件关联均可关闭；关闭后主窗口仍能完成既有业务，且系统不遗留注册项、后台进程或隐式监听。

## 4. 范围与优先级

### 4.1 P0：Windows Stable 阻断项

| 能力 | 范围 |
|---|---|
| 桌面壳 | 主窗口、单实例、托盘、窗口恢复、外链隔离 |
| Runtime Supervisor | 依赖图、健康、迁移门禁、进程所有权、退出与有限恢复 |
| 桌面发行 | Sidecar、安装器、配置迁移、版本清单、更新、回退、卸载 |
| 状态与诊断 | 启动页、运行状态中心、错误解释、日志入口、脱敏诊断包 |
| 数据与安全 | 受保护密钥、精确 Origin、桌面会话认证、最小 Capability、签名校验 |

### 4.2 P1：V4 产品身份阻断项

| 能力 | 范围 |
|---|---|
| 全局快捷键 | V4-0 通过 Windows、浏览器和常用 IDE 冲突矩阵冻结默认组合；可配置、可关闭、冲突可解释 |
| 快速输入窗口 | 文本提问、流式回答、继续到主窗口、失败保留草稿 |
| 通知联动 | 打开对应上下文、稍后提醒；不承载高风险确认 |
| 受控文件接入 | `.md` / `.txt` 单文件预览与临时本地分析；明确不支持类型 |
| 按住说话 | 复用 V3-4a 本地 STT/TTS，不做常驻唤醒词 |
| 可选开机启动 | 默认关闭、设置可撤销、不会形成失败启动循环 |

P0 和 P1 都必须在 V4 Stable 前完成；P0 先于 P1 开发。任何 P1 功能不得反向侵入核心业务层。

### 4.3 P2：不承诺进入 V4

- 多文件批量分析；
- PDF、DOCX、XLSX、PPTX、图片和压缩包；
- 自定义通知动作；
- 快速窗口插件或多种独立小组件；
- 唤醒词和免按键连续语音；
- 文件夹监控和自动知识入库。

## 5. 界面与窗口架构

### 5.1 界面清单

| 界面 | 形态 | 核心职责 |
|---|---|---|
| 启动窗口 | 原生轻量窗口 | 1 秒内反馈真实启动阶段，异常时提供下一步 |
| 主窗口 | 单实例主窗口 | 承载 V3-4b `/chat` 双翼工作台和全部完整业务 |
| 快速窗口 | 临时前台窗口 | 快捷文字/语音输入、轻量流式回答、跳转同一会话 |
| 运行状态中心 | 主窗口内页面或抽屉 | 查看依赖、版本、降级原因，执行受控诊断动作 |
| 首次启动向导 | 主窗口流程 | 依赖检查、旧配置导入、隐私与默认行为设置 |
| 托盘菜单 | 系统托盘 | 打开、快速提问、状态摘要、开机启动、完全退出 |
| 恢复视图 | 启动窗口/主窗口错误态 | 重试、打开状态中心、查看日志、导出诊断、退出 |

### 5.2 窗口规则

1. 主窗口、快速窗口和启动窗口都属于同一个 App 实例。
2. 第二次启动只聚焦已有实例；不得再次启动 Core、Companion 或迁移。
3. 主窗口关闭默认最小化到托盘；用户首次关闭时说明该行为，并可改为“直接完全退出”。
4. “完全退出”停止 App 自有 Sidecar，保留外部 Docker Desktop 和 Ollama。
5. 快速窗口按 `Esc` 隐藏；正在发送时先取消前端等待但不伪造服务端取消结果。
6. 快速窗口不可长期抢占焦点，不默认常驻最前，不覆盖全屏游戏或安全桌面。
7. 窗口位置超出当前显示器时恢复到主显示器可见区域。
8. 外部链接一律交给默认浏览器；协议和文件激活先通过白名单解析。

### 5.3 快速窗口交互

- 默认宽度适合一行到数行输入，不复制完整双翼工作台；
- `Enter` 发送，`Shift+Enter` 换行，`Esc` 隐藏；
- 首次输入创建一个标准“快速对话”；窗口未显式新建且 30 分钟内有后续输入时继续该会话；
- 超过 30 分钟未交互后，下次发送创建新对话，旧对话仍在正常会话历史中；
- 回答支持流式文本和引用摘要；出现审批、工具详情、复杂卡片或错误恢复时，引导“在主窗口继续”；
- 发送失败保留草稿并提供重试；未发送草稿默认只保存在当前 App 进程内，完全退出后不落盘；
- 成功发送后不得复制消息；主窗口打开的是同一 conversation/message。

## 6. 核心用户旅程

### 6.1 首次安装与迁移

1. 用户运行签名安装包并选择 per-user 安装。
2. 安装器创建开始菜单入口、卸载项和可选桌面快捷方式。
3. 首次启动检查 WebView2、Docker/PostgreSQL、Ollama 与 Jarvis Sidecar。
4. 检测到旧源码配置时显示导入预览；用户选择导入项后再执行。
5. 密钥进入受保护存储，普通设置进入用户配置目录；旧文件不删除。
6. 核心依赖就绪后进入现有 Onboarding 或主工作台。
7. 用户可测试通知、麦克风和全局快捷键；开机启动默认关闭。

验收：全新安装和旧版本迁移均无需终端；取消迁移不修改旧配置；依赖缺失有准确说明。

### 6.2 日常启动与恢复

1. 用户从开始菜单、桌面或托盘打开 Jarvis。
2. 1 秒内出现启动反馈，展示 `preflight → dependencies → database → core → companion → ready`。
3. 成功后进入上次主窗口状态；可选依赖失败时显示降级标识。
4. 再次双击只聚焦已有窗口。
5. 用户完全退出时，只停止 Jarvis 自有进程。

验收：正常路径不出现终端窗口；失败页面能指出对象、原因和下一步；无重复进程。

### 6.3 快捷提问

1. 用户在任意普通桌面应用按下 Jarvis 全局快捷键。
2. 快速窗口获得输入焦点，用户输入问题并发送。
3. Jarvis 在窗口内流式返回轻量回答。
4. 用户继续追问，或点击“在主窗口继续”查看完整上下文和侧翼卡片。
5. 若请求需要审批，快速窗口只显示需要在主窗口确认，不提供批准按钮。

验收：快捷输入与主窗口只产生一条用户消息和一条对应回答；审批边界不变。

### 6.4 按住说话

1. 用户在快速窗口或主窗口按住麦克风按钮；可选的按住说话快捷键默认关闭，由用户自行配置。
2. Windows 首次请求麦克风权限；拒绝后显示恢复方式。
3. 松开即结束录音，本地 STT 生成可编辑转写。
4. 用户确认发送；自动发送默认关闭。
5. 若启用语音播报，TTS 继续遵守安静时段和敏感内容设置。

验收：取消录音不发送；录音原始数据不上传云端、不写入业务库；转写可编辑。

### 6.5 通知返回

1. Jarvis 通过 Windows Toast 展示提醒。
2. 普通提醒展示“打开”“稍后 10 分钟”；敏感提醒隐藏正文。
3. “打开”聚焦现有 App 并导航到稳定对象引用对应的上下文。
4. “稍后 10 分钟”调用现有 snooze 语义并显示结果。
5. 过期或无效引用打开通知中心并说明对象已不可用，不能误开其他对象。

验收：Toast 不能批准工具或付费动作；重复点击保持幂等；深链不接受任意 URL。

### 6.6 文件交给 Jarvis

1. 用户把一个 `.md` 或 `.txt` 文件拖入主窗口，或在资源管理器选择“使用 Jarvis 打开”。
2. App 展示文件名、类型、大小、来源、处理方式和隐私提示，不立即读取并发送全文。
3. 用户选择“临时本地分析”并确认；内容仅进入受控本地文件分析流程。
4. 若后续需要云模型，必须再次走现有隐私确认；用户可取消。
5. 结果进入标准对话；源文件不被修改、移动或自动写入知识库。

V4 Stable 的最小支持范围：单个 UTF-8/UTF-8 BOM `.md` 或 `.txt`，不超过 2 MiB。其他编码、目录、快捷方式、网络位置、加密文件和其他扩展名均拒绝并解释原因。

验收：未确认前不执行分析；不支持文件不会无响应；日志不记录全文；文件路径不能越过本次显式授权。

### 6.7 查看状态与修复

1. 用户从启动失败页、托盘或设置打开运行状态中心。
2. 状态中心展示 Jarvis App、Core、PostgreSQL、Ollama、Companion、本地语音和可选 Worker。
3. 每项展示 `ready / degraded / blocked / stopped`、版本、最后检查时间和简短原因。
4. 用户可执行重新检查、重启 Jarvis Core、打开日志目录、导出脱敏诊断包或查看依赖修复说明。
5. 状态中心不得提供任意 Shell 输入框或误导性的“一键修复全部”。

验收：显示状态与 Supervisor 一致；诊断包无 Token、Cookie、Prompt 正文或私人文件内容。

### 6.8 更新与回退

1. App 在空闲时检查 Stable/Beta 对应通道，不在对话、审批或工具执行中强制重启。
2. 用户查看版本、影响和重启要求后主动安装。
3. 更新前停止 Sidecar、验证备份和兼容性，再验证签名与校验和。
4. 二进制更新失败恢复上一版本入口；数据库迁移不做未经演练的自动 downgrade。
5. 回退结果和下一步可见。

验收：篡改包被拒绝；N-1 → N 和 N 启动失败回退均有自动化与人工证据。

## 7. 功能需求

### 7.1 App 生命周期

| 编号 | 级别 | 需求 | 验收要点 |
|---|---|---|---|

## 8. 领域对象与接口契约

### 8.1 统一桌面意图

所有原生入口先转换为窄的 `DesktopIntent`，再由 Adapter 调用已有业务接口：

```text
DesktopIntent
  id: UUID
  source: quick_window | notification | file_handoff | tray
  kind: open_chat | send_message | open_notification | snooze_notification | analyze_local_text
  object_ref: 可选的稳定对象引用
  payload_ref: 受控临时载荷引用，不是任意路径或命令
  requested_at: UTC 时间
  correlation_id: 诊断关联 ID
```

约束：

- `DesktopIntent` 不是业务事实源，不长期保存消息正文或文件全文；
- `kind` 为封闭枚举，不能用字符串透传任意命令或 URL；
- 业务结果由 FastAPI 返回，Desktop Shell 只负责展示和导航；
- 相同 `id` 的重试必须幂等或返回既有结果。

### 8.2 稳定对象引用

通知和窗口跳转使用 `ObjectRef(type, id, version)`，首版允许：

- `conversation`；
- `notification`；
- `approval`（只允许打开，不允许批准）；
- `task`；
- `workspace_panel`（只允许白名单面板类型）。

引用解析必须在 Core 侧验证当前用户、对象存在性和权限。前端路由不能被当作授权依据。

### 8.3 Runtime Supervisor 接口

调用方只依赖以下能力：

```text
start(profile) -> RuntimeSnapshot
stop(reason) -> StopResult
retry(component_id) -> RuntimeSnapshot
status() -> RuntimeSnapshot
subscribe() -> RuntimeEventStream
export_diagnostics() -> DiagnosticArtifact
```

进程发现、端口所有权、迁移、超时、重试、Job Object、日志和 Adapter 差异全部封装在 Supervisor 内部，避免散落到 Tauri UI、PowerShell 和 Python Companion。

## 9. 数据、隐私与安全规则

1. PostgreSQL 继续保存会话、提醒、审批、记忆和业务事件；桌面壳只保存窗口偏好、快捷键和无正文运行状态。
2. 未发送的快速窗口草稿默认只驻留内存，完全退出时清除。
3. 原始语音只进入本地临时目录或内存，转写完成或取消后按策略删除。
4. 文件分析只读取用户本次明确选择的文件；不得后台扫描父目录或最近文件。
5. 文件正文、Prompt 正文、Token、Cookie、数据库凭证不得写入运行日志或诊断包。
6. 敏感 Toast 不显示正文；锁屏可见性遵从 Windows 和 Jarvis 双重设置中的更严格值。
7. Desktop Shell 不持有数据库凭证；前端不持有长期 Core Token。
8. `jarvis://` 或等价协议只接受白名单 action 和严格 ID，拒绝命令、文件路径和外部 URL 注入。
9. 快捷键和开机启动属于用户偏好，可导出但不包含敏感内容。
10. 删除 App、删除配置和删除业务数据是三个独立动作，卸载不得默认删除后两者。

## 10. 非功能需求

### 10.1 性能

| 指标 | 目标 |
|---|---|
| 原生启动反馈 | 双击后 ≤ 1 秒 |
| 热启动到主工作台 | p50 ≤ 8 秒，p95 ≤ 15 秒 |

| 托盘恢复 | p95 ≤ 1.5 秒 |
| 快捷键到可输入 | 热运行 p95 ≤ 500 ms |
| 快速窗口首个流式字符 | 不劣于同条件主窗口超过 500 ms |
| 通知点击到界面反馈 | 热运行 p95 ≤ 1.5 秒 |

冷启动、包体积和工作集预算由 V4-0 实测、V4-1 冻结；报告必须记录设备、依赖、缓存、模型和网络条件。

### 10.2 可靠性

- 50 次启动/完全退出循环无 App 自有孤儿进程；
- 连续 20 次快捷唤醒无重复窗口或丢失焦点；
- 端口冲突测试不终止非 Jarvis 进程；
- 24 小时待机及多次睡眠/唤醒无重启风暴；
- 数据库迁移失败 100% 阻断 `ready`；
- 通知重复激活、快速消息重试和更新重试具备幂等证据；
- 7 天真实使用无 P0/P1 数据、启动或安全问题。

### 10.3 可用性与无障碍

- 所有核心动作可使用键盘完成；焦点顺序可预测；
- 快速窗口和启动状态具有屏幕阅读器可读名称；
- 颜色不是状态的唯一表达，错误同时提供文字和图标；
- 支持 Windows 100%、125%、150%、200% 缩放；
- 中文为默认界面语言，技术错误附可复制错误码，不直接暴露堆栈；
- Reduce Motion 模式关闭非必要动画。

### 10.4 可观测性

- 每次启动生成 correlation ID；
- 状态变化、组件版本、耗时、重试和退出原因使用结构化日志；
- 日志有轮换和大小上限；
- 默认不上传遥测。产品指标在本地聚合，公开发行若要外发必须另立需求并征得同意；
- 诊断包生成前后各执行一次脱敏检查。

## 15. V4 发布门禁

Jarvis OS 只有同时满足以下条件，才可以标记 V4 Windows Stable：

- P0、P1 需求全部完成，没有未解释的范围缩减；
- V4-0 技术结论和 ADR-0015 与最终实现一致；
