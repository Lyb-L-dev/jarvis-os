## 2. 观察口径

每次观察按会话记录，样本不足时保留原始计数，不计算误导性的百分比。

| 维度 | 记录方法 | 退出判断所需证据 |
|---|---|---|
| 面板唤起准确性 | 记录“应出现 / 实际出现 / 误出现 / 漏出现”及触发话题 | 覆盖六类面板；误唤起和漏唤起均有可定位样本，未发现阻断性模式 |
| 数据密度 | 记录空态、正常态、拥挤态及每侧同时可见面板数 | 空态可理解、正常态可扫描、拥挤态不遮挡中央对话；每侧上限仍为 3 |
| 旧页面深链 | 记录从双翼跳往结构化页面的目标与原因 | 明确哪些深链必须长期保留；未验证前不删除入口 |
| 旧时间线回退 | 在 Flag 关闭路径执行真实聊天与刷新 | 聊天、刷新和侧栏状态均无回归，回退不依赖清理 localStorage 或数据库 |
| 错误与恢复 | 记录 API 错误、面板关闭/恢复、移动端焦点归还 | 无数据丢失或权限越界；错误可局部恢复且不阻塞中央对话 |

### 2026-08-12 样本说明

- 该轮由自动化浏览器模拟真实输入并连接本机正式 API，不是系统所有者的长期自然使用统计；
- 组合请求命中 `career`、`memory`、`knowledge`、`growth`、`orchestrator`、`approval`，左右各 3 个，未超过容量上限；
- “What day of the week is today?” 没有改变面板栈，作为本轮唯一负样本；
- 桌面、笔记本和手机截图保存在忽略提交的 `artifacts/v3-4b-gray/`，只作本地走查证据；
- 浏览器中存在历史演练对话，面板状态会按当前对话最新用户消息恢复。后续自然使用观察应以独立会话记录分子、分母，避免把历史恢复误计为新唤起；
- 六个面板的结构化深度页逐一走查结果：`/career`、`/memory`、`/knowledge`、`/growth`、`/observatory`、`/approvals` 均为 HTTP 200；任务编排原 `/agents` 死链已在本轮修复，并加入浏览器门禁。

### 隔离意图矩阵说明

- 矩阵是前端匹配规则和会话隔离的合成回归门禁，不是用户自然使用样本，也不计入真实唤起准确率；
- 正向覆盖求职中英文、记忆、知识、成长、编排中英文、审批，以及求职 + 记忆 + 成长混合场景；
- 负向覆盖普通日期问题、普通系统解释，以及 `coffer`/`researcher` 两个英文子串边界；
- 每例创建独立临时会话、从空工作区启动，在面板状态写入后停止/拦截模型流，最后归档会话，避免历史状态和模型响应污染结果。

### 本地观察账本

- 2026-08-12 起，双翼工作台将无正文观察事件追加到浏览器 `localStorage` 的 `jarvis:v3-4b:observation:v1`，最多保留最近 500 条；
- 事件只包含随机观察会话 ID、时间、视口、面板 ID、来源、是否被关闭抑制、左右栈数量和深链目标；不包含提示词、回答、业务会话 ID、记忆、文件或审批正文；
- 工作台命令栏的“导出观察”生成带 schema 版本和隐私说明的 JSON，供后续人工核对自然使用样本；账本是灰度证据，不是业务事实源；
- 灰度开始后已有 1 个非门禁会话被更新，其中 10 条用户消息可识别出 8 条来自既有自动化，剩余 2 条由于上线账本前没有面板事件，标记为不可回溯候选，不补算准确率；
- 观察账本上线后的自然会话才进入正式分子、分母；合成矩阵和门禁事件继续单列，不混入自然使用准确率。

## 4. 进入 V3-5 的退出条件

只有同时满足以下条件，才把 V3-4b 标记为完成并进入 V3-5：

1. 已收集覆盖六类面板的实际使用样本，并保留分子、分母和异常场景；
2. 桌面、普通笔记本和手机均完成至少一轮真实任务走查；
3. 旧页面深链保留/替代清单已形成，没有未经验证的入口删除；
4. Flag 开启和关闭两条路径再次通过，关闭路径无需清理浏览器状态即可恢复；
5. 阻断性问题清零，其余问题已明确进入 V3-5 或后续 Issue；
6. 观察结论回写 `JARVIS_OS_V3_DELIVERY_LOG.md`，再更新主计划阶段状态。

当前已完成一轮代理操作的三视口走查、六条深链清单，并上线无正文观察账本，但六类面板仍缺少账本上线后的足量独立自然使用样本；第 1、5、6 项仍未满足，因此 V3-5 未开始。
