# Jarvis OS v1.1 使用与恢复指南

## 日常使用

启动时双击项目根目录的：

```text
启动 Jarvis.cmd
```

启动程序会自动：

1. 检查并启动 Docker Desktop；
2. 启动 PostgreSQL；
3. 更新数据库结构；
4. 启动 Jarvis Core；
5. 启动 Windows 提醒与语音组件；
6. 启动自动备份 Worker；
7. 启动中文网页并打开浏览器。

停止时双击：

```text
停止 Jarvis.cmd
```

停止 Jarvis 不会停止 Docker Desktop，也不会删除数据库和备份。

## 新电脑首次安装

### 准备软件

- Windows 10 或 Windows 11；
- Docker Desktop；
- Python 3.12 或更高版本；
- Node.js 22 LTS；
- Ollama；
- 至少 16 GB 内存；
- 建议保留 10 GB 以上可用磁盘空间。

### 安装 Jarvis 依赖

在项目目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

该脚本会创建 `.env`、Python 环境，并安装后端、网页和 Windows
Companion 依赖。

### 准备本地模型

```powershell
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull bge-m3
powershell -ExecutionPolicy Bypass -File .\scripts\setup-mem0-shadow.ps1
```

如果本机 Ollama 中的模型名称不同，需要同步修改 `.env` 中的
`OLLAMA_MODEL`。Mem0 准备脚本只复用已经安装的 Qwen 与 BGE-M3，不会自动
下载模型；缺少任一模型时会停止并明确提示。

### 配置模型

只在本机用文本编辑器打开 `.env`，不要把文件内容发到聊天、邮件或截图中。

- MiMo 按量 API：使用 `sk-` 密钥和普通 API 地址；
- MiMo Token Plan：使用订阅管理页显示的专用地址、`tp-` 密钥，并设置
  `MIMO_TOKEN_PLAN_ENABLED=true`；
- 关闭 Token Plan 接入：把 `MIMO_TOKEN_PLAN_ENABLED` 改为 `false`；
- 小米当前套餐规则对非编程自定义后端有限制，启用后存在暂停服务或封禁密钥风险；
- DeepSeek：可以填写 API Key，但每次实际付费调用仍要求确认；
- Ollama：不需要 API Key；
- OpenClaw：保持 `OPENCLAW_ENABLED=false`。

配置完成后，双击 `启动 Jarvis.cmd`。

### 安装离线中英文男声

首次使用原创中英文男声时执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-voice.ps1
```

脚本会安装本地语音运行时，并下载中文男声和美式英语男声。模型保存在
`.data\voice`，合成固定使用 CPU，不占用 独立显卡 的 4 GB 显存。项目路径包含
中文时，脚本还会建立 `C:\tmp\jarvis-voice-model` 和
`C:\tmp\jarvis-voice-en-model` 两个兼容目录联接；它们不复制、移动或删除原始
模型。

重复运行脚本会检查现有文件，不会在模型完整时重新下载。

英语模型使用的训练数据许可为 CC BY-NC-SA 4.0，适合当前个人、非商业使用。
未来如果发布商业版本，需要更换或重新复核英语声线许可。

启动后可以运行一次本机预检：

```powershell
.\scripts\preflight.ps1
```

它只检查依赖、Docker、本地模型、服务状态和已配置 Provider 数量，不显示
API Key。

## 连接平板专用终端

平板通过 USB 显示 Jarvis，电脑仍负责模型推理、数据保存、Obsidian、提醒和
API Key 管理。此方式不会把 Jarvis 开放到局域网。

### 第一次准备

先阅读 Google 的 Android SDK 许可。确认接受后，在项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File `
  .\scripts\install-tablet-tools.ps1 `
  -AcceptAndroidSdkLicense
```

脚本只下载 Google 官方 Android Platform Tools，保存到项目的 `.tools\android`
目录，并检查 `adb.exe` 的 Google 数字签名。没有明确许可参数时不会下载。

### 平板设置

1. 在平板“设置”中开启开发者选项；
2. 在开发者选项中开启“USB 调试”；
3. 使用支持数据传输的 USB 线连接电脑；
4. 平板出现“允许 USB 调试”时，核对这是自己的电脑后再允许；
5. 先双击 `启动 Jarvis.cmd`；
6. 再双击 `连接 Jarvis 平板.cmd`。

连接脚本会创建两个 USB 反向端口，并让平板浏览器打开：

```text
http://127.0.0.1:3000/tablet
```

这个地址在平板上看起来仍是本机地址，但通过 USB 分别连接电脑的网页和 API。
首次打开后可以使用浏览器“添加到主屏幕”，以后以横屏独立窗口显示。

### 日常使用与断开

- “全屏”会尝试进入浏览器全屏并锁定横屏；
- “屏幕常亮”只在当前页面活动时阻止自动熄屏，关闭页面后自动释放；
- 所有文字对话和停止生成结果都会保存在电脑数据库；
- 中文/EN 按钮选择语音转写语言；
- 首次启用麦克风时会提示：浏览器转写可能使用系统在线服务，不要口述敏感内容；
- 不使用时双击 `断开 Jarvis 平板.cmd`，它只删除 Jarvis 的两个 USB 映射；
- 长期不用时建议关闭平板的 USB 调试。

Jarvis 的连接脚本不会安装 APK、解锁 Bootloader、Root 平板，也不会读取或写入
平板文件。目前没有启用 Wi‑Fi 调试、局域网访问或公网访问。

## 总览核心状态

总览中央的 J-Core 会用状态和动效说明 Jarvis 当前在做什么：

- **待命**：系统已连接，等待你的操作；
- **聆听**：用于预览未来语音接收状态；
- **思考**：页面正在读取数据，未来也用于检索和推理反馈；
- **执行**：正在执行“同步系统”等明确操作；
- **警报**：核心就绪检查失败或部分关键依赖需要检查。

核心下方的五个状态按钮目前是视觉预览，只会切换界面状态，不会调用模型、
修改数据或产生 DeepSeek 费用。页面首次加载、手动同步和核心异常会自动覆盖预览
状态。

## 模块遥测条

Chat、成长、英语、情报、投资、记忆和知识库顶部现在都有四格遥测条。它用于
回答“当前在哪个视图、有哪些待处理内容、系统使用什么路线、当前安全边界是什么”。

遥测条是只读状态，不是新的操作按钮：

- 绿色通常表示已连接、有效或可以使用；
- 青色表示一般信息和当前标准路线；
- 紫色表示知识、深度模式或受控权限；
- 黄色表示需要关注或仍由你决定；
- 红色表示连接或来源异常。

Chat 遥测中的“执行中”表示正在生成回答；“仅本地”表示隐私模式已启用；
“知识增强”表示会按每篇笔记的本地/云端权限检索。改变这些行为仍需使用输入台
中的模型、隐私和知识库控件。

## 模型评测与执行过程

“评测”页面使用 6 项固定、非私人的个人场景测试 MiMo、本地 Qwen 和
DeepSeek。建议先用 MiMo 运行一项，再用本地 Qwen 运行相同项目；只有确实需要
比较复杂能力时才选择 DeepSeek。

- MiMo 是默认主模型；
- 本地 Qwen 适合检查离线和隐私任务表现；
- DeepSeek 每次测试都会单独要求确认付费；
- 未配置模型会显示“未配置”，不能运行；
- 测试失败不会自动切换其他模型，否则结果无法公平比较；
- 得分来自明确的内容、安全和长度检查，不使用另一个付费模型充当裁判；
- “符合预期 / 不符合”是你的个人判断，会进入后续统计，但不会自动改路由。

同一页面的“记忆实验室”使用另外 10 项固定合成场景，比较现有规则、本地 Qwen
和 Mem0：

- Mem0、Qwen、BGE-M3 和 pgvector 全部在本机运行；
- 不调用 MiMo 或 DeepSeek，不产生模型钱包费用；
- Mem0 单项在当前电脑上约需 50–60 秒；
- 所有结果只是影子候选，不会进入正式记忆或聊天上下文；
- “正确 / 部分正确 / 错误”只记录人工评测，不会把候选转正；
- 关闭 `V2_MEM0_SHADOW_ENABLED` 不影响聊天和正式记忆；
- `V2_MEM0_CHAT_SHADOW_ENABLED` 在 Sprint 28 必须保持 `false`。

## 审批中心与工具安全

从左侧“审批”进入 Approval Center。这里统一显示工具动作和 DeepSeek 单次任务授权。

- R0 本地读取和 R1 内部草稿可以自动完成，但会留下审计记录；
- R2 文件、日历、邮件、外部账号和浏览器提交必须先预览；
- 你可以修改预览、拒绝或批准；
- 批准后仍不会自动执行，需要在“待执行”中再次点击执行；
- 批准只允许使用一次，过期或参数改变后必须重新预览；
- 投资交易、支付、删除数据和凭据操作永远没有 Agent 执行入口。

受控文件工具的目标限制在项目 `.data/tool-sandbox`，只允许 `.md`、`.txt` 和 `.json`。真实日历写入、邮件发送、浏览器提交和外部账号修改仍处于“已预留、未连接”状态。

首次进入时会看到一条 `sprint29/acceptance-20260802.md` 的验收预览。它没有写入文件；你可以直接拒绝，或在确认内容后批准，再到“待执行”完成写入。

## n8n 自动化 Provider

审批中心底部的“隔离自动化通道”显示 Jarvis 专用 n8n 的运行状态。它与电脑上已有的 n8n 完全分开，编辑器不对外开放，入口只监听本机并要求 HMAC 签名。

当前可以安全使用：

- “读取沙盒日历”：只读取 `jarvis_sandbox` 测试数据，不创建或修改事件；
- “生成本地邮件草稿”：草稿只保存在 Jarvis 执行结果中，不会发送邮件。

页面中的“真实账号：未连接”和“外部写入：已关闭”是当前正确状态。Jarvis 尚未要求你登录 Google、Outlook 或任何邮箱，也不会在后台保存这些账号的凭据。Provider 显示离线时，聊天、记忆、成长、研究和投资功能仍可继续使用。

如果需要停用该功能，把 `.env` 中的 `V2_N8N_PROVIDER_ENABLED` 改为 `false` 后重新启动 Jarvis。不要删除或修改电脑上原有的 `n8n` 容器；Jarvis 只管理 `jarvis-n8n` 和 `jarvis-n8n-ingress`。

在“设置 → 最近模型调用”中点击“查看过程”，可以看到选择模型、知识检索和
生成回答三个步骤。记录不会显示你的提问、回答、笔记正文或 API Key。

## 语音人格与自动播报

打开“提醒”页面，在语音设置中可以选择：

- 自动选择：自动识别中文、英文和混合文本，优先使用对应离线男声，失败时自动
  切换 Windows 系统语音；
- 本地男声：明确优先使用离线模型，失败时仍保留系统语音兜底；
- Windows 语音：跳过本地模型，直接使用系统声音；
- 沉稳：默认人格，以简短开场说明提醒类别和优先级；
- 简洁：压缩开场语，适合提醒较多时使用；
- 朴素：尽量直接朗读标题和正文。

页面同时显示 Desktop Companion 上报的引擎状态。调整人格、语速或音量后点击
保存；“测试语音”会先显示确认，再创建一条立即到期的语音提醒。自动播报依然
遵守免打扰、暂停、每日提醒上限和每小时语音上限。

中英混合提醒会保留原始顺序，例如“先生，Your English review is ready.
现在开始 shadowing practice.” 会依次使用中文、英语、中文、英语声线。语言
判断是本地字符规则，不调用 MiMo、DeepSeek 或 Ollama。

为了避免读出网页格式，Jarvis 会在播报副本中清理 Markdown、链接和多余空白，
但不会修改提醒原文。本地语音不是电影配音演员的声纹克隆，而是独立的原创风格。

## Obsidian 知识库

知识库页面已经连接当前 Vault，只会读取：

```text
F:\obsidian\NewHub\NewHub\Jarvis
```

点击“立即扫描”可以更新 Markdown 索引；使用搜索框可以按正文、标题、路径和
类型查询。点击“在 Obsidian 中打开”会调用 Obsidian URI。

Jarvis 不读取 Vault 的其他笔记，不访问 `.obsidian`，也不会静默覆盖用户手工
修改的文件。

受控归档规则：

- 已确认且有效的长期记忆自动进入 `Jarvis/Memory/`；
- 已完成的每日情报自动进入 `Jarvis/Intelligence/Daily/`；
- 周复盘、已完成英语会话、投资理由和投资复盘需要在知识库页面手动点击归档；
- 重复执行不会重复创建同一来源的文件；
- 如果你在 Obsidian 中修改过目标文件，Jarvis 会保留原文件，把待更新版本放入
  `Jarvis/_review/`，并在知识库页面显示冲突；
- Vault 暂时不可用时，聊天、提醒、情报和其他 Jarvis 功能继续运行。

“自动同步”按钮可以立即检查长期记忆和每日情报；后台也会定时检查。手动候选
只有在你点击归档后才会写入 Obsidian。

### 在对话中使用知识库

Chat 输入框下方的“知识库”开关默认开启。开启后，Jarvis 会按当前问题检索
已索引笔记；真正使用的来源会显示在回答下方，点击 `[K1]`、`[K2]` 可以直接
在 Obsidian 中打开。

知识库页面每篇笔记有两项独立权限：

- “参与对话检索”：关闭后，任何模型都不会使用这篇笔记；
- “允许云端”：开启前会再次确认，开启后相关摘录才可能发送给 MiMo 或经你
  明确确认后的 DeepSeek。

新笔记默认参与本地检索，但默认“仅限本地”。因此当前使用 MiMo 标准模式时，
只有你明确允许云端的笔记能够进入回答；隐私模式或本地模式可以使用全部已启用
检索的笔记。关闭 Chat 中的“知识库”开关可以让单次提问完全不检索 Obsidian。

### 把对话沉淀为知识

完成一段有长期价值的对话后，可以点击 Chat 右上角“沉淀知识”。Jarvis 会：

1. 只调用本地 Qwen 整理当前对话；
2. 在知识库页面生成一份可编辑草稿；
3. 等你修改并点击“确认并写入 Obsidian”；
4. 把确认内容写入 `Jarvis/Conversations/`。

未确认草稿不会进入 Obsidian，也不会参与后续回答。点击“放弃草稿”只会放弃
整理结果，不会删除原始对话。生成后的笔记仍然默认“仅限本地”，如果确实需要
MiMo 使用，再在笔记权限中单独开启“允许云端”。

### 从草稿提取记忆与行动

知识草稿还可以继续变成 Jarvis 能复用的结构化内容：

1. 在知识库页面检查并修改草稿；
2. 点击“提取记忆与行动”；
3. 等待本地 Qwen 提出少量候选；
4. 在“知识提炼候选”中逐条查看类型、来源、内容和提炼理由；
5. 选择“保存为长期记忆”“创建成长任务”“创建核验任务”或“忽略”；
6. 如需保留完整原文，再点击“确认并写入 Obsidian”。

三种候选的含义：

- 长期记忆：稳定偏好、目标、决定、经验或长期事实；确认后默认仅限本地模型；
- 行动任务：明确可执行的后续行动；确认后出现在成长任务中；
- 待核验问题：尚无可靠结论的问题；确认后只创建“核验：”任务，不当作事实。

提炼和写入 Obsidian 是两个独立出口，可以都使用，也可以只选择其中一个。
如果先写入 Obsidian，尚未提炼的归档内容仍会保留“提取记忆与行动”入口。
Jarvis 不会在后台自动提炼历史草稿，也不会自动接受任何候选。

重复点击不会重复创建记忆或任务；API Key、密码、验证码、证件号等敏感信息
不能保存为长期记忆。修改草稿后，尚未接受的旧候选会被清除并允许重新提炼，
已经接受的结果及来源记录不会被删除。

## 数据导出与备份

在“设置 → 自动备份与恢复验证”中可以：

- 导出个人数据：下载一个不包含 API Key 的 JSON 文件；
- 立即备份：创建 PostgreSQL 恢复点；
- 验证可恢复：在临时数据库中恢复并检查，不修改当前数据。

自动备份约每 20 小时创建一次，默认保留最近 30 份。目录是项目下的
`backups`；当前电脑对应：

```text
.\backups
```

同一块硬盘上的备份不能抵御整块硬盘损坏。重要阶段应把已验证的 `.dump`
和对应 `.manifest.json` 一起复制到移动硬盘。

## 真正恢复数据库

只有当前数据库损坏、迁移失败或明确需要回退时才执行。

1. 双击 `停止 Jarvis.cmd`；
2. 在设置页记录中确认目标恢复点曾通过恢复验证；
3. 打开 PowerShell；
4. 输入完整确认文字执行：

```powershell
.\scripts\restore-backup.ps1 `
  -BackupPath ".\backups\jarvis-目标恢复点.dump" `
  -Confirmation "RESTORE JARVIS"
```

恢复程序会先再次验证目标备份，再给当前数据库创建安全备份，然后恢复到临时
数据库。全部成功后才交换数据库名称，恢复前的数据库仍会保留。

## 常见故障

### 网页打不开

先双击 `停止 Jarvis.cmd`，等待几秒，再双击 `启动 Jarvis.cmd`。如果仍失败，
查看 `.runtime` 中对应的错误日志。

### Docker 未就绪

手动打开 Docker Desktop，等待状态变成 Running，再启动 Jarvis。

### 本地模型不可用

```powershell
ollama list
```

确认存在：

- `qwen3:4b-instruct-2507-q4_K_M`；
- `bge-m3:latest`；
- `jarvis-memory-qwen:latest`。

前两个缺失时由你手动执行对应的 `ollama pull`；两者都存在后，再运行
`scripts\setup-mem0-shadow.ps1` 创建 16K 本地别名。Jarvis 不会静默下载模型。

### 没有语音或桌面提醒

- 确认 Jarvis 没有处于免打扰或暂停状态；
- 检查 Windows 通知权限和音量；
- 在提醒页确认中文男声、英语男声和 Windows 备用语音状态；
- 打开提醒页查看每个渠道的投递结果；
- 如果本地男声不可用，重新执行 `scripts\install-voice.ps1`；
- 重新启动 Jarvis，让 Windows Companion 重新注册。

## 安全原则

- Jarvis 网页和 API 只监听本机；
- 不在多人共用的 Windows 账户下保存真实 API Key；
- 不把 `.env`、`backups` 或个人数据导出上传到公开网盘；
- 不允许投资模块自动交易；
- 不在主机安装 OpenClaw，直到虚拟机隔离和插件审计通过；
- DeepSeek 付费调用必须逐次确认。

需要重新执行发布检查时：

```powershell
.\scripts\check.ps1
.\scripts\dependency-audit.ps1
```

第二条命令需要联网读取 Python 与 npm 漏洞数据库。
