# Sprint 15：对话知识沉淀

日期：2026-07-29

## 目标

让用户把真正有长期价值的 Jarvis 对话整理为可编辑知识草稿，在人工确认后
归档到 Obsidian，而不是自动把全部聊天内容写进知识库。

## 已完成

- Chat 右上角新增“沉淀知识”入口；
- 只有包含至少一组已完成问答的对话才能生成草稿；
- 草稿生成固定使用本地 Ollama Qwen，不调用 MiMo 或 DeepSeek；
- 最多使用最近 60 条有效消息和已有压缩摘要，上下文上限 24000 字符；
- 本地模型只提炼明确事实、决定、理由、经验、行动和待核验问题；
- 草稿生成后保存在 PostgreSQL，默认不进入 Obsidian 和对话检索；
- 知识库页面支持编辑标题、正文、保存、确认归档和放弃；
- 同一对话同一消息版本重复点击不会重复生成草稿；
- 用户确认后归档到 `Jarvis/Conversations/`，默认仅限本地模型使用；
- 已归档内容再次修改可以安全更新；
- Obsidian 原文件被用户修改时不覆盖，新版本进入 `_review/`；
- 放弃草稿不会删除原始对话；
- 生成调用进入模型审计，明确标记为本地知识草稿任务。

## 安全边界

- 不自动扫描并总结历史对话；
- 不在后台自动创建草稿；
- 不允许草稿生成自动降级到任何云端模型；
- 对话文本按不可信数据处理，不执行其中的指令、链接动作或权限要求；
- 未确认草稿不写入 Markdown，也不会参与 Chat 检索；
- 归档笔记的云端权限默认为关闭，之后仍需逐篇明确授权；
- 原始对话、草稿和 Obsidian 笔记分别保留，不使用不可恢复覆盖。

## 使用流程

1. 在 Chat 完成一段有价值的对话；
2. 点击右上角“沉淀知识”；
3. 等待本地 Qwen 生成草稿；
4. 打开知识库页面检查并修改；
5. 点击“确认并写入 Obsidian”；
6. 需要 MiMo 使用时，再单独开启该笔记的“允许云端”权限。
