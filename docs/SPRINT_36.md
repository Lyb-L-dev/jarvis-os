# Sprint 36：Proactive Engine

## 状态

已完成。Jarvis 现在会基于目标、任务、情报与习惯信号，在合适的时间主动生成建议——默认只生成建议与草稿，不执行动作，不在后台调用任何模型，并遵守静默时段、每日上限与去重冷却。

## 目标

- 从固定提醒升级为基于目标、情报、任务和习惯的主动建议；
- 默认只生成建议和草稿；
- 后台不静默调用 DeepSeek（也不调用任何模型）；
- 继续遵守静默时段、频率限制和审批边界。

## 已交付

### 建议引擎（`services/proactive.py`）

纯本地规则生成，四个信号源：

- **任务**（行动）：逾期任务（优先级 5）、24 小时内到期（优先级 4）、今日计划（优先级 3），最多 3 条；
- **周复盘**（复盘）：本周还没有复盘记录且存在任务时建议做周复盘（优先级 2）；
- **情报**（学习）：最近 48 小时相关度 ≥ 4 的新情报，最多 2 条，提示打开原始链接核对；
- **习惯**（学习）：英语复习已到期时建议完成一轮复习（优先级 3）。

### 安全与频率边界

- 静默时段：复用 `NotificationPreference` 的静默窗口（默认 22:30–08:00），静默中扫描直接跳过并返回 `quiet_hours`；
- 每日上限：默认每天最多 10 条（`proactive_daily_cap`），超限返回 `daily_cap`；
- 单次扫描上限：默认最多 5 条（`proactive_max_per_scan`）；
- 去重冷却：同一来源（任务/情报/复习等）在 24 小时内不重复建议；
- 不调用模型：引擎不导入、不调用任何模型网关，后台工作进程零模型费用；
- 只建议不动作：没有写任务、改计划、发消息等副作用入口；接受/忽略只改变建议自身状态。

### Proactive API（`/api/v1/proactive`）

- `GET /proactive/overview`：待处理数、今日生成/上限、冷却窗口、静默时段状态与说明；
- `GET /proactive/suggestions`：建议列表，支持按状态与来源过滤；
- `POST /proactive/scan`：手动触发扫描（同样受静默与频率限制）；
- `POST /proactive/suggestions/{id}/accept` / `dismiss`：接受或忽略建议。

### 后台工作进程

- 默认每 30 分钟扫描一次（`proactive_poll_seconds`），接入 `app/main.py` 生命周期；
- 与情报/监控/知识归档工作进程一样随 API 启停，测试环境不启动；
- 扫描失败静默跳过，不影响 API。

### Proactive 页面

- 侧边栏 SYSTEMS 分组新增入口，地址 `/proactive`；
- 指标卡：待处理、今日生成/上限、静默时段状态、去重冷却、引擎状态；
- 建议卡片：类型（行动/复盘/学习）、来源、优先级、标题、理由、时间；
- 待处理/已接受/已忽略三个标签页，接受或忽略即时生效；
- 手动扫描按钮（返回生成数与跳过原因）；
- 说明横幅：只产生建议与草稿、不执行动作、不在后台调用任何模型；
- 15 秒自动刷新；
- 视觉验收截图：`artifacts/proactive-engine-sprint36.png`。

### 稳定细节

- SQLite 返回无时区时间戳，服务内统一按 UTC 归一化后再比较，避免时区崩溃；
- 建议来源按 `source_type + source_id` 去重，周复盘使用稳定 UUID（由周起始日派生）；
- 生成逻辑不依赖任何模型输出，结果确定、可解释、零费用。

## 设计说明

- “主动”体现在定时扫描与信号聚合，不体现在未经确认的动作上；建议永远只是建议；
- 静默时段、频率限制与审批边界复用既有通知偏好与 Tool Gateway 原则，不另起炉灶；
- 建议可解释：每条都带来源与理由；接受/忽略即学习，去重窗口避免重复打扰。
